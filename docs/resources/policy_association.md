# gravitino_policy_association Resource

Attaches policies to a catalog, schema, table, view, fileset, topic, model or function in a metalake. Only direct associations are managed: policies inherited from a parent object are ignored by Read and are never removed by destroy. Gravitino exposes no DELETE for an association, so destroy sends one associatePolicies request with policiesToRemove for every policy in state.

## Example Usage

```terraform
# Attach existing policies directly to a metadata object. Each policy must list
# the object type in its supported_object_types. Adding or removing entries
# updates the association in place; destroy detaches every policy this resource
# manages.
resource "gravitino_policy_association" "orders_masking" {
  metalake         = gravitino_metalake.example.name
  object_type      = "TABLE"
  object_full_name = "sales.orders"
  policies         = [gravitino_policy.data_retention.name]
}
```

## Import

Import is supported using the following syntax:

```shell
# Import an existing policy association by metalake, object type and object full name.
terraform import gravitino_policy_association.example my_metalake.TABLE.sales.orders
```

## Schema

### Required

- `metalake` (String) The metalake name. Changing this forces the association to be recreated.
- `object_full_name` (String) The full name of the metadata object relative to the metalake, for example 'my_catalog' for a CATALOG, 'my_catalog.my_schema' for a SCHEMA and 'my_catalog.my_schema.my_table' for a TABLE. Do not prefix it with the metalake name. Changing this forces the association to be recreated.
- `object_type` (String) The metadata object type. One of: CATALOG, SCHEMA, TABLE, FILESET, TOPIC, MODEL, VIEW, FUNCTION. VIEW and FUNCTION require Gravitino >= 1.3.1 and are rejected on an older server with an explicit diagnostic. Columns cannot carry a policy.
- `policies` (Set of String) The names of the policies to attach directly to the object. Adding and removing entries is applied in place through associatePolicies. Each policy must list this object_type in its supported_object_types; a mismatch is rejected before the request is sent, naming the allowed types. Set it to [] to detach every policy this resource manages while keeping the resource. Policies inherited from a parent object are not part of this set.

### Read-Only

- `id` (String) Composite identifier in the format 'metalake.object_type.object_full_name'.
