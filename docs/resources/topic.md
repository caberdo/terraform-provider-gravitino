# gravitino_topic Resource

Manages a Gravitino topic within a metalake catalog schema.

## Example Usage

```terraform
resource "gravitino_topic" "events" {
  metalake = gravitino_metalake.example.name
  catalog  = gravitino_catalog.kafka.name
  schema   = gravitino_schema.example.name
  name     = "user_events"
}

resource "gravitino_topic" "configured" {
  metalake = gravitino_metalake.example.name
  catalog  = gravitino_catalog.kafka.name
  schema   = gravitino_schema.example.name
  name     = "audit_logs"
  comment  = "Topic for audit log events"
  properties = {
    "retention.ms" = "604800000"
    "partitions"   = "6"
  }
}
```

## Import

Import is supported using the following syntax:

```shell
# Import an existing topic by metalake, catalog, schema and topic name.
terraform import gravitino_topic.example my_metalake.my_catalog.my_schema.my_topic
```

## Schema

### Required

- `catalog` (String) The catalog name. Changing this forces a new topic to be created (Gravitino topics cannot be moved between catalogs).
- `metalake` (String) The metalake name. Changing this forces a new topic to be created (Gravitino topics cannot be moved between metalakes).
- `name` (String) The topic name. Changing this forces a new topic to be created: Gravitino supports no rename update for topics.
- `schema` (String) The schema name. Changing this forces a new topic to be created (Gravitino topics cannot be moved between schemas).

### Optional

- `comment` (String) A comment describing the topic. Removing the attribute (or setting it to an empty string) clears the comment: Gravitino has no removeComment update, so the provider sends an updateComment update with an empty newComment.
- `properties` (Map of String) Key-value properties for the topic. Adding, changing and removing entries is applied in place; only keys that appear in this map are written to state. Omit the attribute to keep the current properties, or set it to {} to remove all of them.

### Read-Only

- `audit` (Object) Audit information for the topic. Gravitino rewrites lastModifier/lastModifiedTime on every update, so this stays unknown in the plan and is written on every read. (see [below for nested schema](#nestedatt--audit))
- `id` (String) The compound identifier in the format metalake.catalog.schema.topic.
