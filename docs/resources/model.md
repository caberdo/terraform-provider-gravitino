# gravitino_model Resource

Manages a Gravitino model within a metalake, catalog, and schema. Model artifacts are not attached to the model itself but to a gravitino_model_version.

## Example Usage

```terraform
resource "gravitino_model" "example" {
  metalake = gravitino_metalake.example.name
  catalog  = gravitino_catalog.ml.name
  schema   = gravitino_schema.example.name
  name     = "fraud_detector"
  comment  = "ML model for fraud detection"
  properties = {
    "framework" = "pytorch"
  }
}

output "latest_model_version" {
  description = "The version number Gravitino assigned to the newest model version."
  value       = gravitino_model.example.latest_version
}
```

## Import

Import is supported using the following syntax:

```shell
# Import an existing model by metalake, catalog, schema and model name.
terraform import gravitino_model.example my_metalake.my_catalog.my_schema.my_model
```

## Schema

### Required

- `catalog` (String) The catalog name. Changing it forces a new model to be registered, because Gravitino cannot move a model between catalogs.
- `metalake` (String) The metalake name. Changing it forces a new model to be registered, because Gravitino cannot move a model between metalakes.
- `name` (String) The model name. Renaming it sends a `rename` update to Gravitino.
- `schema` (String) The schema name. Changing it forces a new model to be registered, because Gravitino cannot move a model between schemas.

### Optional

- `comment` (String) A comment describing the model.
- `properties` (Map of String) Key-value properties for the model.

### Read-Only

- `audit` (Object) Audit information for the model. (see [below for nested schema](#nestedatt--audit))
- `id` (String) The compound identifier in the format metalake.catalog.schema.model.
- `latest_version` (Number) The latest version number of the model. Gravitino assigns the number and increases it every time a model version is linked to this model.
