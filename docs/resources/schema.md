# gravitino_schema Resource

Manages a Gravitino schema within a metalake and catalog.

## Example Usage

```terraform
resource "gravitino_schema" "example" {
  metalake = gravitino_metalake.example.name
  catalog  = gravitino_catalog.hive.name
  name     = "example_schema"
}

resource "gravitino_schema" "full" {
  metalake = gravitino_metalake.example.name
  catalog  = gravitino_catalog.hive.name
  name     = "analytics_schema"
  comment  = "Schema for analytics data"
  properties = {
    owner = "data-team"
  }
}
```

## Import

Import is supported using the following syntax:

```shell
# Import an existing schema by metalake, catalog and schema name.
terraform import gravitino_schema.example my_metalake.my_catalog.my_schema
```

## Schema

### Required

- `catalog` (String) The catalog name. Changing it forces the schema to be recreated, because a schema is addressed by its metalake, catalog and name.
- `metalake` (String) The metalake name. Changing it forces the schema to be recreated, because a schema is addressed by its metalake, catalog and name.
- `name` (String) The schema name. Changing it forces the schema to be recreated: the Gravitino schema update API only supports property updates, not renaming.

### Optional

- `comment` (String) A comment describing the schema. Changing it forces the schema to be recreated: the Gravitino schema update API only supports property updates, not comment updates.
- `properties` (Map of String) Key-value properties for the schema. Adding, changing and removing entries is applied in place; no other schema attribute can be updated in place.

### Read-Only

- `audit` (Object) Audit information for the schema. The server sets last_modifier and last_modified_time on every in-place update, so this attribute deliberately has no UseStateForUnknown plan modifier: an update writes the refreshed values to state. (see [below for nested schema](#nestedatt--audit))
- `id` (String) The compound identifier in the format metalake.catalog.schema.
