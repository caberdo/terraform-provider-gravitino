# gravitino_tag Resource



## Example Usage

```terraform
resource "gravitino_tag" "pii" {
  metalake = gravitino_metalake.example.name
  name     = "PII"
  comment  = "Personally Identifiable Information"
}

resource "gravitino_tag" "confidential" {
  metalake   = gravitino_metalake.example.name
  name       = "confidential"
  comment    = "Confidential data requiring special access"
  properties = {
    "classification" = "internal"
    "retention"      = "90d"
  }
}
```

## Import

Import is supported using the following syntax:

```shell
# Import an existing tag by metalake and tag name.
terraform import gravitino_tag.example my_metalake.my_tag
```

## Schema

### Required

- `metalake` (String) The metalake name. Changing this forces a new tag to be created (Gravitino tags cannot be moved between metalakes).
- `name` (String) The tag name. Renaming the tag is applied in place via Gravitino's rename update.

### Optional

- `comment` (String) A comment or description for the tag. Set it to an empty string to clear an existing comment; omitting the attribute leaves the server value untouched.
- `properties` (Map of String) A map of key-value properties for the tag. Removing a property from the map removes it on the server; only keys that appear in this map are written to state. Omit the attribute to keep the current properties, or set it to {} to remove all of them.

### Read-Only

- `audit` (Object) Audit information for the tag. Gravitino rewrites lastModifier/lastModifiedTime on every update, so this stays unknown in the plan and is written on every read. (see [below for nested schema](#nestedatt--audit))
- `id` (String) Composite identifier in the format 'metalake.tag_name'. It changes when the tag is renamed.
- `inherited` (Boolean) Whether the tag is inherited from a parent metadata object. Null when the server does not report it.
